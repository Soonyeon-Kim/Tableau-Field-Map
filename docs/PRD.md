# PRD: Tableau-Field-Map

## 목표

Tableau 워크북(`.twbx`) 안에 흩어진 계산식이 **원본 컬럼에서 출발해 어떤 과정을 거쳐 만들어졌는지**를 한 화면에서 추적하게 한다. 필드 목록이 아니라 **리니지(계보) 파이프라인**을 보여주고, 그 위에서 재사용 실태를 드러내 **계산식 통합·리네임을 제안**한다.

기준 워크북(사내, 비공개)에서 확인된 문제:

- 계산식과 파라미터가 시트·대시보드 전반에 흩어져 있다
- 계산식이 여러 층으로 중첩된다 (원본 컬럼 → … → 시트)
- 수식 유사도 0.88 이상인 쌍이 많다 — 통합하거나 파라미터화할 여지가 크다
- 반대로 소수의 허브 계산식을 수많은 수식이 재사용한다

Tableau Desktop은 필드 하나의 상·하위 계보를 보여주지 않는다. 그래서 지금은 "이걸 고치면 어디가 깨지나"를 사람이 눈으로 따라가는 수밖에 없다.

## 사용자

이 워크북을 유지보수하는 사람(본인)과, 이 워크북을 처음 넘겨받는 팀원. 둘 다 Tableau Desktop은 쓸 줄 알지만 워크북 내부 XML은 모른다. 산출물은 **Tableau 없이 브라우저만으로** 읽을 수 있어야 한다.

쓰는 상황 네 가지:

1. **영향도 분석** — 계산식 하나를 고치기 전에 하류에 무엇이 달려 있는지 확인한다
2. **인수인계** — 워크북을 넘길 때 함께 넘기는 설계 문서
3. **교육** — 팀원이 대시보드 → 시트 → 계산식 → 원본 컬럼의 흐름을 스스로 따라간다
4. **정리** — 중복·미사용 계산식을 찾아 통합하거나 지운다

## 핵심 기능

1. **리니지 그래프** — 필드 하나를 고르면 상류(무엇으로 만들어졌나)를 원본 컬럼까지 좌→우 계층형으로 그린다. 하류는 기본적으로 계산식까지만 그리고 시트·대시보드는 토글로 켠다 — 하류 시트가 아주 많은 원본 컬럼이 있어 전부 그리면 읽을 수 없다. 노드 120개에서 자르고 잘렸음을 표시한다.
2. **의미 설명** — 노드를 클릭하면 수식 원문과 함께 "이 계산식이 무엇을 하는가"를 한국어 한 줄로 보여준다. Claude가 초안을 쓰고 사람이 검수하며, 미검수 설명에는 **초안 배지**를 붙여 확정된 사실과 구분한다.
3. **통합 후보** — 수식을 정규화해 완전 일치 및 유사도 0.88 이상인 쌍을 묶어 제시한다. 접미사만 다른 쌍, `(+)/(-)` 부호 분리, 기간만 다른 쌍처럼 **파라미터 하나로 합칠 수 있는 패턴**을 짚는다.
4. **재사용도·미사용 점검** — fan-in(몇 개 수식이 이 필드를 참조하나)으로 허브와 말단을 가른다. 어떤 시트도 쓰지 않고 어떤 수식도 참조하지 않는 필드는 **미사용 후보**로 따로 모은다.
5. **이름 점검** — 워크북에 이미 존재하는 접두어 패밀리에서 이탈한 필드와 기본 이름이 남은 필드를 지적한다.
6. **두 가지 출력** — `map.html`(인터랙티브)과 `map.md`(git diff로 변경 추적 가능). 같은 JSON에서 렌더한다.

## 제외 사항 (v1)

- **워크북 수정** — 이 도구는 읽기 전용이다. 통합·리네임은 *제안*까지만 하고 `.twb`를 다시 쓰지 않는다. 자동 수정은 되돌리기 어렵고 Tableau가 파일을 다시 저장할 때 무엇이 깨질지 검증할 수단이 없다
- **Tableau Server/Cloud 연결** — 로컬 `.twbx` 파일만 받는다. 서버 연동은 같은 계열의 별도 비공개 도구가 담당한다
- **`.hyper` 데이터 값 읽기** — 스키마와 수식만 다룬다. 실제 데이터 행은 건드리지 않는다
- **코드 안에서의 LLM 호출** — CLI는 stdlib만 쓰고 API 키를 요구하지 않는다. 설명 초안은 Claude 세션이 채운다
- **시트 내부 레이아웃 분석** — 선반(shelf)·마크 카드 배치는 다루지 않는다. "이 시트가 이 필드를 쓴다"까지만
- **다중 워크북 교차 분석** — 한 번에 워크북 하나

## 성공 기준

측정 가능한 것만 적는다.

| 기준 | 판정 |
|---|---|
| 파싱 정확도 | `fixtures.local.json`에 고정한 기준 워크북 실측값(종류별 노드 수·최대 층·순환 0)을 그대로 재현 |
| 환각 없음 | 해석 못 한 필드 참조(`unresolved`)가 0. 0이 아니면 목록을 출력하고 실패한다 — 추측해서 이어 붙이지 않는다 |
| 통합 후보 유효성 | `fixtures.local.json`에 고정한 최소 쌍 수 이상이 잡히고, 접미사만 다른 쌍이 실제로 목록에 오른다 |
| 영향도 정확도 | 표본 계산식 1개의 상·하류가 Tableau Desktop에서 본 것과 일치한다 (눈으로 1건 대조) |
| 재사용성 | 다른 `.twbx` 파일을 인자로 줘도 코드 수정 없이 동작한다 |

## 디자인

- 매일 쓰는 분석 **도구** 톤. 데이터 밀도 우선, 마케팅 톤 금지
- 3분할: 좌(검색 목록) / 우상(그래프) / 우하(수식·설명·제안)
- 노드 색은 종류 5종(원본컬럼·파라미터·계산식·시트·대시보드)만 구분한다. 층은 색이 아니라 위치로 읽힌다
- **근거 강도를 숨기지 않는다.** 통합 후보(강함)와 리네임 제안(약함 — 기준 워크북에서 기본이름 잔존은 거의 없었다)을 같은 확신으로 표시하지 않는다. 미검수 설명에는 초안 배지를 붙인다
